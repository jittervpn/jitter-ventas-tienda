Cómo configurar HTTP Custom con tu CDN CloudFront

Actualizado el 11 de noviembre de 2026, por el equipo de Jitterx Panel Cloud

HTTP Custom es una aplicación para Android que permite crear túneles cifrados desde el móvil. Esta guía te lleva desde cero hasta una conexión funcionando a través de tu CDN CloudFront, y explica cómo comprobar que todo va bien y qué hacer si algo falla.

Qué necesitas antes de empezar

  • Un móvil Android con la app HTTP Custom instalada desde Google Play.
  • Un servicio CDN activo. Si todavía no lo tienes, sigue la guía de cómo contratar tu CDN CloudFront.
  • El usuario y la contraseña SSH de tu propio servidor (el que pusiste como origen del CDN).

Paso 1: copia los datos de tu CDN

Entra a la web, abre la sección CDN y busca tu servicio en Mis servicios CDN. Ahí tienes el host CDN, el puerto 80 y el payload CloudFront, cada uno con su botón de copiar.

Paso 2: configura la app

  1. Abre HTTP Custom y crea una configuración nueva.
  2. En los datos SSH, escribe como servidor el host CDN (termina en cloudfront.net) y el puerto 80, seguidos del usuario y la contraseña de tu servidor: host:80@usuario:contraseña.
  3. Activa la opción de payload personalizado y pega el payload CloudFront de tu servicio.
  4. Guarda la configuración.

Paso 3: conecta y verifica

Pulsa el botón de inicio. El registro de la app mostrará la respuesta HTTP/1.1 101 del WebSocket y después la autenticación SSH. Para comprobarlo, abre en el navegador un sitio que muestre tu IP pública: debería coincidir con la de tu servidor, no con la de tu operador.

Solución de problemas

Error 403 o 404 en el registro

El payload no coincide con tu servicio: revisa que la ruta y el host sean exactamente los de tu tarjeta. Vuelve a copiar el payload con el botón.

Error 502 o 504

CloudFront no logra conectar con tu servidor. Comprueba que el origen sea correcto, que el servidor esté encendido y que acepte WebSocket en el puerto 80. Si cambiaste de servidor, actualiza el origen con Cambiar origen.

«Authentication failed»

El usuario o la contraseña SSH de tu servidor no son correctos. Revísalos respetando mayúsculas y minúsculas.

Conectaba y dejó de funcionar

Mira en la web si tu servicio sigue Activo. Si venció, renuévalo: conservas el mismo host, ruta y payload.

Se desconecta cada pocos minutos

Suele deberse al ahorro de energía de Android. Permite que la app funcione sin restricciones de batería.

Consejo. NetMod y otras apps que aceptan SSH sobre WebSocket con payload se configuran igual: host CDN, puerto 80 y el mismo payload.
